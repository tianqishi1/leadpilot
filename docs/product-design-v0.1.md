# LeadPilot — AI 营销获客系统 产品设计 v0.1

日期：2026-11-17 ｜ 状态：草案（待评审）｜ 配套讨论：获客赛道调研 / GTM 冷启动方案

---

## 0. 定位与边界

**一句话定位**：以「合格线索」为价值原子的多租户 AI 营销获客系统。双引擎（outbound 意向线索 + inbound 内容营销），合规硬门禁，全链路归因闭环。**租户 0 是我们自己**（自用 = 增长引擎 + 活体演示），**租户 N 是商家**（使用 = 拿线索）。

**明确不做（Non-goals）**：
- AI 外呼 / 短信盲发（监管红线）
- 批量矩阵养号、无人值守发布（2026 平台治理红线）
- 通用企业数据库 + 坐席年费（正面打探迹，无胜算）
- 全自动 AI 成交（11x 已证伪）
- 自建多平台发布器（social-auto-upload / 蚁小二等现成轮子）

## 1. 整体设计思路（七条原则）

- **P1 一条流水线，两个平面**：自用与商用共用同一条流水线，差异全部落在租户配置（品牌、行业包、账号、线索池）。Dogfooding 不是营销话术而是架构约束：凡自用用到的能力，必须是租户可配置的产品能力。
- **P2 结果原子化**：价值原子 = 合格线索（qualified lead），不是坐席、不是发文数。线索生命周期中的「验收通过」事件同时是 **计费事件 + 训练样本 + 案例证据**，三位一体。
- **P3 证据先行**：每张线索卡、每条内容宣称都必须带可点击证据。证据库（evidence DB）只收经审计的真实数据；内容工厂引用案例数字时只能从证据库取 → 「战果即广告」成为系统硬约束，杜绝编造（11x 教训）。
- **P4 合规是门禁不是约定**：发布门 / 触达门 / 数据门 / 宣称门，四道硬门禁 + 全量审计日志。策略引擎式实现：规则硬校验，不依赖模型自觉。
- **P5 平台通用、配置值钱**：流水线是 commodity，行业配置包（信号源权重、合格判定 rubric、选题库、话术、承接资产）才是护城河与续费理由。按垂直行业出配置包。
- **P6 人 owning**：每租户一名 owner。Agent 提案、人在门禁批准；每周 ROI 复盘是产品内建流程，不是可选服务。
- **P7 先服务形态、后产品形态**：MVP 允许 concierge（后台半人工）交付，但接口与数据模型按产品化设计；验证通过再固化自动化。

## 2. 用户与核心旅程

### 2.1 租户 0（我们自己）
- Persona：创始人（owner）+ 内容/交付运营 0.5~1 人。
- ICP：靠销售拿业绩的 B2B 中小企业（首选单一垂直行业）；买入信号 = 在招销售 / 在投广告 / 新设分支 / 近期融资扩编。
- 旅程：信号名单 → 带免费线索样品的个性化触达（sample campaign）→ 15 分钟通话看线索卡证据 → 小额试点 → 每周 ROI 复盘 → 订阅 → 案例入证据库 → 新内容。

### 2.2 租户 N（商家）
- Persona：老板 / 销售负责人（owner，拍板+验收）；商家销售（线索消费者）；可选：商家市场人员（内容审批）。
- 旅程：选行业包 + ICP 工作坊（1 次）→ 绑定商家自有真人账号 + 书面「合格线索」定义与验收 SLA → 每日线索digest推企微/飞书 + 内容日历审批 → 销售跟进并 48h 回标 → 无效自动补换 → 每周 ROI 报告 → 扩量/续费。
- 服务形态两档：**Managed（我们代运营，商家审批）** 先行；**Self-serve（商家自运营）** 后期。

### 4.1 线索卡（lead card）示例
```
company: 苏州XX精密机械有限公司
industry_pack: 工业设备
signal: 2026-11-10 发布「销售工程师×5」招聘（证据: 招聘页URL）
        2026-11-02 中标XX产线项目（证据: 招投标公告URL）
inferred_need: 扩销售团队+新产线 → 未来90天采购/拓客预算上升
recommended_opener: 「看到贵司刚中标XX产线并在扩销售团队，我们整理了
                     3条同区域正在询价的采购线索…」
public_contact: 企业公示电话 / 官网表单 / 企微渠道（不使用个人手机号爬取）
confidence: 0.82 ｜ freshness: 7d ｜ status: new
```

### 4.2 线索生命周期（验收=计费=训练 三位一体）
```
new → delivered → accepted(计费事件) → contacted → opportunity → deal
                → invalid(48h内+理由) → replacement_queue → 补换线索
任何状态变更写 lead_event；invalid 理由进 M8 训练集；deal 进证据库(脱敏+授权)
```

### 4.3 内容项与宣称校验
content_item(source_topic, platform_variants[], aigc_label=true,
claims[] → 每条 claim 必须引用 evidence_db 记录或外部证据URL，否则门禁拒绝)。

## 5. 双引擎详细设计

### 5.1 Outbound 意向线索引擎
信号源（按行业包配置权重）：
| 信号 | 来源 | 含义 |
|---|---|---|
| 招聘扩编（销售/客服/产线） | 招聘平台公开页 | 预算扩张、缺线索/缺人 |
| 招投标/中标 | 公共资源交易平台 | 项目预算落地 |
| 新注册/新分支/新开店 | 企业公示数据 API | 新主体=新采购需求 |
| 广告投放中 | 广告库/公开投放痕迹 | 正在花钱买线索=痛点现成 |
| 社媒求购意向 | 平台合规工具/人工辅助采集 | 显式需求 |
| 扩产/融资新闻 | 新闻/公告 | 扩张周期 |

流程：连接器采集 → 实体归一 → ICP 过滤 → 意向评分 → LLM 深度背调（强制引用）→ 线索卡 → 抽检 → digest 推送（企微/飞书）→ 销售跟进 → 48h 回标 → 补换/调优。
**触达边界：系统只交付线索与话术建议，触达由商家人工销售执行；无自动外呼/短信/批量加好友。**

### 5.2 Inbound 内容营销引擎
- 选题 Agent：买家真实问题（知乎问题/搜索词/评论区痛点/竞品内容缺口）→ 每周内容日历提案 → owner 确认。
- 一源多态：知乎长文 / 公众号深度 / 小红书图文 / 抖音+视频号口播脚本；平台语气与格式规范在行业包内。
- 硬门禁：AIGC 显式+隐式标识（GB 45438-2025）；广告法极限词检查；claims 必须来自证据库；**人工批准后才进分发**。
- 分发：social-auto-upload skill / 蚁小二 / 公众号官方 API；每平台 1~2 个真人设账号（租户自有）；限速与平台规则包；发布日志全留痕。
- 承接：评论/私信意向识别 → AI 起草回复（人确认或平台规则内自动）→ 钩子（行业获客成本报告 / ROI 计算器 / 免费线索样品）→ 带平台关键词码的表单/企微 → 线索池（source=inbound）。
- GEO 红利：头条/百家号/搜狐号同源分发，喂 AI 搜索引用源；监控「AI 搜索引用次数」指标。

## 6. 合规与策略硬门禁（横切）

| 门 | 规则 | 实现 |
|---|---|---|
| 发布门 | 人工批准 + AIGC 标识 + 极限词 + claims 证据校验 | 策略引擎硬校验，缺一项拒发 |
| 触达门 | 渠道白名单（人工电话/企微/邮件 opt-in）；频控；opt-out 登记；禁外呼/短信盲发/批量加好友 | 工具 allowlist + 频率限制 |
| 数据门 | 来源合法性白名单；仅企业公示联系方式；PII 最小化；爬取限速与 robots 尊重 | 连接器准入审查 |
| 宣称门 | 案例数字/客户 logo 必须 evidence_db 有审计记录+授权 | 引用校验 |
全量 audit_log；门禁规则版本化；变更过评测门禁。

## 7. 多租户与行业配置包

industry_pack schema（sketch）：
```
icp: {industry, size, region, exclude[]}
signals: [{source, weight, freshness_ttl}]
qualification_rubric: {dimensions[], threshold, 合格定义合同文本}

```
- 租户 0 配置 = 首个行业包 + 「卖获客系统」playbook（sample campaign）。
- 商家 onboarding：选包 → ICP 工作坊 → 账号绑定 → 合格定义签字 → 承接资产配置 → 开跑。目标 ≤1 周。
- 新行业包上线走 shadow → canary → 全量（复用发布演练思路），评测门禁通过才放量。

## 8. 归因、成本与计费

- 归因：每线索带 source_engine / campaign / content_id / platform / keyword_code；内容→线索→商机→成交全链路可查。
- 成本账本：每线索摊 data API + LLM + 人工质检成本；每内容项摊生产+分发成本；ROI = 商机/成交价值 ÷ 成本，按租户/活动/平台出周报。
- 计费事件 = lead_event.accepted；invalid 补换不计费；月度对账单自动生成。
- 定价阶梯：试点包 999~2999 元 / 20~50 条 → 按合格线索 50~300 元/条（行业包定价）或月包 3~8k 含 N 条 → Managed 服务费 → 年费仅在 ROI 被商家销售团队确认 2~3 个月后提。
- 锚定话术：对比商家现有单线索成本（广告/探迹/销售人力），不对比我们的成本。

## 9. 反馈与评测闭环

- 回标（accepted/invalid+理由）→ qualification rubric 与评分权重迭代提案 → 人审 → 评测门禁（历史回标集回归）→ 生效。
- 内容归因 → 选题加倍/砍掉提案 → owner 周确认。
- eval_case 集：线索质量（回标历史）、内容合规（门禁红队用例）、宣称真实性（抽查）。
- 配置/模型变更：shadow 跑 → canary 小流量 → 指标护栏自动回滚。

## 10. Dogfooding 专项设计（租户 0）

- sample campaign 产品化：「免费样品触达」作为 outreach playbook 模板（商家亦可改用为「免费诊断/报告」式触达）。
- 证据库流水线：租户 0 的 deal/ROI 数据脱敏+审计后入 evidence_db → 内容工厂宣称门唯一来源 → **宣传内容自动等于真实战果**。
- 租户 0 专属看板：样品→试点转化率、试点→付费转化率、CAC 回收周期（目标<3月）、内容→线索成本、AI 搜索引用次数。
- 架构验收标准：租户 0 用到的任何能力，若不能以租户配置表达，视为设计缺陷（P1 的检查器）。

## 11. MVP 范围与 90 天路线

| 阶段 | 时间 | 交付 | 形态 |
|---|---|---|---|
| P0 自用验证 | W1~4 | 信号名单(半人工)+LLM背调流水线+线索卡推企微；内容工厂3平台+人审；归因先DB表+周报脚本 | concierge |
| P1 设计伙伴 | W5~8 | 3~5家同垂直商家 Managed；验收/补换工作流；计费手工对账 | 服务+薄产品 |
| P2 产品化v1 | W9~12+ | 控制台(审批/线索池/看板)；计费计量；行业包#2；评测门禁 | 产品 |

**MVP 不做**：无人值守发布、多账号矩阵、AI 外呼、self-serve onboarding、>2 垂直行业、重 CRM（企微/飞书+导出代替）。

## 12. 指标与止损线

- 线索接受率 ≥60~70%；线索→商机转化率 > 租户现有来源；60 天续费 ≥70%。
- 无效补换 SLA 48h 达成率 ≥95%；合规事故 = 0；内容→线索成本逐月下降。
- 止损：样品送出后销售不愿打/打不通 → 改信号源与背调，**禁止加大触达量**；试点→付费 <20% → 换行业或换合格定义，不扩规模。

## 13. 风险与对策
| 风险 | 对策 |
|---|---|
| 信号源反爬/ToS | 优先官方 API 与公开页限速；社媒意向走平台合规工具或人工辅助 |
| 平台治理变动 | 规则包版本化+人审门；账号真人设少量 |
| 线索质量纠纷 | 合同合格定义+证据+48h 补换 |
| 巨头跟进 | 垂直深度+按结果计费+证据信任 |
| 数据陈旧 | freshness TTL + 交付前复核 |
| PII/合规 | 数据门+opt-out+审计 |

## 15. v0.2 增量（2026-11-17）：互动信号获客设计（评论/点赞/点击/收藏）

### 15.1 三层可行性结论
- **L1 自有内容互动（第一方，主战场）**：
  - 评论：抖音开放平台「视频评论管理」能力（授权后 API 拉评论列表+回复）；公众号评论 API；小红书专业号/聚光评论管理；视频号助手。AI 意向识别 → 回复/引导私信/留资组件。
  - 私信/留资：官方线索产品。抖音企业号私信自动回复+留资组件（表单/智能电话/落地页），飞鱼 CRM 线索 API 推送可接 M7 线索池；小红书聚光/私信通「进线→开口→留资」三段计费 + 表单留资 + 线索直播私信卡/表单卡（2026 线索经营产品通案）。用户主动同意，完全合规。
  - 点击：自有落地页/小程序/企微渠道码（带参）= 第一方点击+归因；平台侧点击多为聚合数据，无个体身份。
- **L2 点赞/收藏/点击（平台行为）**：**官方不开放身份名单导出**。唯一合规变现路径 = 官方广告人群包（聚光 DMP「笔记互动人群」、巨量互动人群）→ 重定向投放（留资目标）→ 私信/表单留资 → 线索。需广告预算；数据不出平台。
- **L3 他人内容互动（竞品/行业 KOL 评论区截流）**：技术可行但合规灰→黑（ToS + PIPL 公开信息合理范围 + 2026 平台风控：小红书 5 月留资新规、AI 实时预审；非合规聚合工具封禁主体同比 +62%）。**不入核心流水线**。仅允许：聚合级意向/选题挖掘（不留个人身份）喂 M3 选题 Agent；或人工合规舆情监测。

### 15.2 意向分层（intent_tier）与入池规则
```
T1 主动留资(表单/电话/加企微) > T2 私信开口 > T3 显式需求评论 > T4 提问评论
> T5 收藏 > T6 点赞 > T7 点击/浏览
T1~T2 直接入线索池；T3~T4 AI识别+人确认入池；T5~T7 不入 lead 表，
进 audience_pack 表（重定向培育），预算门禁控制投放。
```

### 15.3 模型与门禁增量
- lead schema 增加 source_type（outbound_signal / inbound_content / engagement_comment / engagement_dm / ad_lead_component / channel_qr / landing_page）与 intent_tier。
- 新增表 audience_pack（platform, pack_id, source_interaction_type, size, budget_cap, retarget_campaign）。
- M1 新增连接器类：第一方互动信号（自有评论 API、飞鱼/聚光线索推送、渠道码、落地页埋点）。
- M6 增加「互动意向识别 → 留资组件引导」；回复发送遵守平台导流规则。
- 触达门新增硬规则：**禁止对非第一方互动用户自动私信/批量互动（反截流）**。
- 增长 loop：自然内容产生互动 → DMP 互动人群包 → 付费重定向留资 → 留资成本随人群精度下降；指标增加「互动→留资转化率」「单留资成本（聚光/飞鱼口径）」。
- Non-goals 增补：评论区截流自动私信、点赞/收藏名单导出类爬虫。

## 16. v0.3 增量（2026-11-17）：钉钉通道决策

**结论：加，但作为「交付/协作适配器」加，不作为线索来源加；分发渠道角色留到 PMF 后。**

### 16.1 三个角色分开评估
| 角色 | 结论 | 理由 |
|---|---|---|
| 交付/协作通道（线索digest、验收回标、内容审批、周报） | ✅ 加 | 首选垂直行业（制造/建材/物流/贸易等传统中小企业）钉钉渗透率高；onboarding 原则=跟随商家现有办公栈；钉钉互动卡片原生支持按钮回调（Stream 模式免公网回调地址），验收闭环可在聊天内完成 |
| 线索来源 | ❌ 不加 | 钉钉是内部办公工具，买家不在上面；**禁止爬钉钉群成员当线索**（与反截流同一条合规线） |
| 产品分发渠道（应用市场/酷应用/AI 助理上架） | ⏸ PMF 后 | 触达钉钉存量商家、信任转移；非 MVP |

### 16.2 适配器设计
- M9 抽象 push_channel 接口：send_digest / send_card / on_callback；企微/飞书/钉钉三适配器同接口。
- 租户配置 office_stack: [wecom | feishu | dingtalk]，onboarding 必问「你们平时用哪个」，按栈启用；Tenant 0 用自用栈。
- 验收/审批事件统一写 lead_event / approval，与通道无关；每张卡片带 web 控制台兜底链接。
- 钉钉 MVP：自定义机器人 webhook 推 digest（0.5~1 天）；**限流 20 条/分钟/机器人 → digest 合并为每日 1~2 条**（与现有 digest 设计天然契合）。
- 钉钉 v1：企业内部机器人 + 互动卡片（Stream 回调）做验收/无效/审批按钮（2~3 天）。
- 钉钉 v1+：宜搭表单/CRM 连接器或 webhook 导出，供商家把线索落进自有系统。
- 隔离与安全：每租户独立机器人/群，禁止跨租户群；卡片 payload 过数据门（仅企业公示联系方式）。
- 对照：企微群机器人为单向 webhook，按钮回标需自建应用+回调；飞书卡片支持回调。故互动验收优先在设计伙伴实际使用的栈上实现（预计钉钉或企微自建应用）。
